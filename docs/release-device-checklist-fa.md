# چک‌لیست تأیید امضا و آزمایش دستگاه — ODIN Assistant

این چک‌لیست عمداً بین موفقیت CI و تأیید انتشار واقعی تفاوت می‌گذارد. تا وقتی موارد «دستی/دستگاه واقعی» انجام نشده‌اند، نسخهٔ تولیدی تأیید نمی‌شود.

## A. تنظیم امضای Release در GitHub

در مخزن، به **Settings → Secrets and variables → Actions → New repository secret** بروید و این چهار Secret را با مقادیر keystore خصوصی release تعریف کنید:

- `ANDROID_KEYSTORE_BASE64`: محتوای فایل JKS/keystore به صورت Base64، بدون افشای فایل در مخزن.
- `ANDROID_KEYSTORE_PASSWORD`: رمز keystore.
- `ANDROID_KEY_ALIAS`: نام alias کلید انتشار.
- `ANDROID_KEY_PASSWORD`: رمز کلید alias.

این مقادیر را در issue، chat، log یا commit قرار ندهید. فایل keystore را به Git اضافه نکنید. اگر پروژه از قبل کلید انتشار معتبر دارد، از همان کلید استفاده کنید؛ تولید کلید جدید می‌تواند به مشکل به‌روزرسانی نصب‌های قبلی منجر شود.

### معیار پذیرش امضا
1. اجرای build روی tag انتشار انجام شود.
2. مرحلهٔ `Verify signature` با نتیجهٔ موفق تمام شود.
3. خروجی `apksigner verify --print-certs` گواهی را نشان دهد.
4. fingerprint با fingerprint کلید رسمی مورد انتظار تطبیق داده شود.
5. فقط APK همان اجرای تأییدشده در GitHub Release منتشر شود.

## B. تست روی دستگاه واقعی

### ماتریس پایه
- نصب تازه و ارتقا از نسخهٔ قبلی، اگر نسخهٔ قبلی موجود است.
- Android نسخهٔ هدف و حداقل نسخهٔ پشتیبانی‌شدهٔ پروژه.
- اجرای تحلیل در foreground، قطع و وصل اینترنت، پاسخ کند و timeout.
- ورود به background، قفل صفحه، خروج اجباری، restart دستگاه و رفتار سرویس پس‌زمینه.
- اعلان‌ها: مجوزها، کانال اعلان، جلوگیری از اعلان تکراری و بازشدن درست اپ از اعلان.
- WebView: نمایش فارسی، لینک خارجی، خطاهای شبکه و جلوگیری از crash.
- ژورنال/تنظیمات پس از بستن و بازکردن برنامه و پس از ارتقا.
- مصرف باتری و پایداری در اجرای حداقل ۳۰ دقیقه‌ای.

### شواهد لازم
برای هر اجرا ثبت شود: مدل دستگاه، نسخهٔ Android، نسخهٔ اپ، نتیجهٔ هر مورد، زمان/مراحل بازتولید خطا و logcat مرتبط با حذف اطلاعات حساس. هیچ موردی را فقط بر اساس موفقیت build علامت «تأییدشده» نزنید.

## C. وضعیت فعلی این مخزن

- CI تست‌های خودکار و ساخت APK را اجرا می‌کند.
- artifact قبلی ساخته شد اما امضای release آن اجرا تأیید نشد؛ این artifact unsigned است.
- اجرای تست دستگاه فیزیکی از GitHub Actions یا این محیط انجام نشده است. تا زمانی که دستگاه واقعی در دسترس و ماتریس بالا اجرا نشده باشد، این مورد **باز** باقی می‌ماند.
