**دامنه:** مرور اسناد اصلی و نقاط مرجع معماری، تست، انتشار و امنیت در مخزن.

> تست‌ها، بررسی لاگ زندهٔ CI، آزمون روی دستگاه واقعی یا بک‌تست بازار نیست.

## ۱. وضعیت محصول

- **پلتفرم فعال انتشار:** Android (WebView + JavaScript و پل نیتیو Java).
- **ویندوز:** توسعهٔ محصول از v0.22.0 منجمد شده؛ آخرین نسخهٔ ویندوزِ مستندشده
  v0.21.0 است. کد Python/UI باقی مانده و بخشی از ابزارهای parity و منبع حقیقت
  نسخه/تم است.
- **معاملهٔ خودکار:** وجود ندارد؛ برنامه تحلیل و پیشنهاد سیگنال می‌دهد.
- **قیمت و کندل بازار:** هر دو موتور فقط از Twelve Data استفاده می‌کنند؛ هر کاربر به
  API Key شخصی نیاز دارد. برای هر نماد یک درخواست M15 ارسال و H1/H4 از آن ساخته
  می‌شوند. منبع جایگزین یا fallback قیمت فعال نیست؛ تقویم اقتصادی، اخبار و تأییدیهٔ
  TradingView منابع شواهد جداگانه‌اند.
- **لایسنس:** HMAC آفلاین و قفل دستگاه حفظ شده است. این مدل در برابر استخراج
  secret از برنامهٔ توزیعی مصون نیست؛ محدودیت در بازبینی امنیتی ثبت شده است.

## ۲. معماری کنونی

- هستهٔ Contract-Based + Plugin-Driven برای registry، قراردادها، lifecycle،
  event bus و pipeline.
- موتور Python نقش اوراکل و محیط تست برای موتور JavaScript اندروید را دارد؛
  انجماد رابط ویندوز به معنی حذف موتور Python نیست.
- مسیر سیگنال شامل دریافت داده، تحلیل، ژورنال، لایه‌های فاندامنتال/داوری و
  دروازهٔ توافق استراتژی‌ها است. جزئیات در سند معماری پلاگین نگهداری می‌شود.
- لایهٔ اندروید شامل WebView، Bridge.java، سرویس رصد پس‌زمینه و اعلان‌ها است.

## ۵. کارهای باز و ریسک‌ها

1. **بک‌تست معتبر هنوز کار مستقلی است.** تغییر زمان با --as-of به‌تنهایی replay
   تاریخی نیست. ارزیابی عملکرد باید دادهٔ تاریخی مرتب‌شده، جلوگیری از lookahead،
   ترتیب برخورد TP/SL، spread/slippage/هزینه و گزارش تعداد نمونه، win rate،
   میانگین R، expectancy و drawdown را لحاظ کند.
2. **پل HTTP:** ریدایرکت‌ها به‌صورت دستی با سقف تعداد، محدودیت همان میزبان و منع
   HTTPS→HTTP دنبال می‌شوند؛ allowlist میزبان‌ها و تست‌های امنیتی اختصاصی بازند.
3. **Backup Android:** نیازمند تصمیم صریح محصول/حریم خصوصی و آزمون رفتار روی
   نسخه‌های Android هدف است.
4. **لایسنس آفلاین:** HMAC فعلی بنا بر تصمیم مالک حفظ شده؛ خصوصی‌کردن مخزن در
   آینده secret تعبیه‌شده در APK را محرمانه نمی‌کند.
5. **ارجاعات قدیمی:** ابزارها و متن Release باید به مخزن فعلی
   Suushian/Odin-Assistant اشاره کنند، نه مخزن تاریخی.

## ۶. مسیر پیشنهادی ادامهٔ کار

1. پیش از تغییر معماری، قراردادهای پلاگین و تست‌های parity را بخوانید.
2. پس از هر تغییر، تست مرتبط و workflow مربوطه را اجرا/بررسی کنید.
3. قابلیت بک‌تست را به‌عنوان پروژه‌ای جدا با روش‌شناسی مالی شفاف پیاده‌سازی کنید؛
   نرخ برد به‌تنهایی معیار کافی نیست.
4. مستندات وابسته را همراه تغییر کد به‌روزرسانی کنید و از نگه‌داشتن آمار بدون
   تاریخ یا روش اندازه‌گیری پرهیز کنید.
